## B1｜Google Colabでoff-target予測モデルを学習する

自分で取得した測定データで、ガイドRNAと候補DNAの配列からSpCas9のoff-target活性を予測するニューラルネットを作ります。公開SURRO-seqデータを仮入力にしてColabで学習と評価の手順を組み、入力を自分の測定データに差し替えます。成果物は、再実行できるノートブック、モデルの重み、評価表、実行ログです。

### まず、やりたいことを伝える

最初のプロンプトでは、何を予測したいかを自分の言葉で伝えます。例えば、次のように始めます。

> 自分で取得したoff-targetの測定データを使って、ガイドRNAと候補DNAの配列から予測するニューラルネットを作りたいです。Google Colabで手順を組む間は公開データを仮入力にし、自分のデータに差し替えて、学習に使っていないガイドでどの程度予測できるか確かめたいです。

返ってきた内容を読み、次に何を頼むかを一段階ずつ考えます。[共通の5段階](../README.md#agent-workflow)のうち、環境の準備はColabのCPUランタイムで行います。

### 手順の作成に使う仮入力データ

| 取得先 | 使うデータ |
| --- | --- |
| [PanらのSURRO-seq論文・Figure 3](https://doi.org/10.1038/s41467-022-31543-6)・[Supplementary Data 3（XLSX）](https://static-content.springer.com/esm/art%3A10.1038%2Fs41467-022-31543-6/MediaObjects/41467_2022_31543_MOESM6_ESM.xlsx) | LibBのガイドと候補配列、SpCas9とMOCKの測定結果。論文でフィルタ後に残った7,140候補のうち、753件が有意なindel検出と判定された。 |
| [NCBI GEO GSE206347](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE206347)・[NCBI BioProject PRJNA850372](https://www.ncbi.nlm.nih.gov/bioproject/PRJNA850372) | 同じ研究の登録先。仮入力には上の処理済み表を使う。 |
| [LinとWongのCRISPR-Net](https://doi.org/10.1002/advs.201903562) | ガイドと候補の配列の組をニューラルネットに入力する先行研究。当日は1層の隠れ層を持つ小さなモデルで試す。 |

仮入力のラベルには論文の判定を使い、有意なindelが検出されたLIOT・HIOTを **1**、測定した範囲で有意な検出がなかったNSOTを **0** とします。低カバレッジなどで除外された行や判定不明の行は集計から外します。仮入力で得た評価値は、SURRO-seqの条件に対する結果として記録します。候補配列は細胞内のレポーターで測定されているため、内在性座位での編集効率を調べる場合には、別の測定データで評価が必要です。

### Colabで手順を作り、自分の測定データに差し替える

以下は各段階の到達点です。どの条件を次の依頼に含めるかは、手元のデータや直前の結果を見て決めます。

1. **環境を用意する。** [Google Colab](https://colab.research.google.com/)のCPUランタイムを開きます。Python、PyTorch、pandas、openpyxl、scikit-learnのバージョンを記録し、補足表が読めるところまで確認します。[Colabのランタイム案内](https://research.google.com/colaboratory/runtime-version-faq.html)
2. **学習スクリプトを作る。** ガイドと候補の組を1行にまとめます。ガイドの20塩基と候補の23塩基（PAMを含む）を同じ向きにそろえ、A/C/G/Tをone-hot encodingします。ラベルやindel頻度は入力に含めず、配列だけを使います。PyTorchで小さな全結合ネットワークを作り、二値分類として学習させます。ガイドの20塩基配列を単位に学習・検証・テストに分け、同じガイドが複数の組に入らないようにします。分割はseedを固定し、各組に両クラスが含まれるか確認します。
3. **小さな入力でテストする。** 仮入力から手で確認できる数行を選び、配列の向き、ミスマッチ数、ラベルの割り当てを照合します。同じガイドが分割をまたがず、モデルが1行につき1つのスコアを返すことを確かめます。条件を調整する場合は検証用の結果を使います。
4. **ログを取りながら本解析を行う。** 仮入力で学習から評価まで通ったら、自分の測定データに差し替えて学習します。自分のデータでもガイド単位で分け、最後に学習に使っていないガイドで評価します。同じテスト行で、ミスマッチが少ない順に並べた場合とニューラルネットを比較します。評価表にはガイド数、候補数、陽性数、Average Precision（AP）を載せます。余裕があればprecision–recall曲線を描き、CFDなどの既存スコアも、採点できる同じテスト行で比較します。データの出典、フィルタ条件、分割、seed、学習時のloss、評価値をログに残し、ノートブックとモデルの重みと一緒に保存します。

差し替えに備え、ガイド配列、候補配列とPAM、測定条件、測定値、ラベルの判定基準をそろえます。自分のデータのラベルは、その測定法に合わせて定義します。測定していない候補と、測定したうえで有意な検出がなかった候補は別に扱います。陰性の判定や評価用のガイドが足りない場合は、仮入力で手順を通し、自分のデータで学習・評価するために足りない項目を整理します。非公開データの実行先は、所属先で利用が認められている環境を選びます。

## B2｜Off-target予測ソフトウェアの正確性と網羅性を比べる

同じガイドを入力したとき、Cas-OFFinderとCRISPORが既知のoff-target部位をどれだけ拾い、候補にどんな違いが出るかを調べます。成果物は、ガイド別の比較表と実行ログです。

### まず、やりたいことを伝える

> 同じガイドをCas-OFFinderとCRISPORで調べて、編集が確認された部位をそれぞれ何件拾えるか比べたいです。候補が多いツールほど、実測でもよく当たるのか確かめたいです。

この目的を自分の言葉で伝えたら、[共通の5段階](../README.md#agent-workflow)に沿って次の依頼を考えます。環境にはDockerかcondaを使います。

### 比較に使う公開データ

| 取得先 | 使うデータ |
| --- | --- |
| [Haeusslerらの補足表2](https://doi.org/10.1186/S13059-016-1012-2)・[再現用リポジトリ](https://github.com/maximilianh/crisporPaper)・[NCBI GEO GSE61586](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE61586) | 元のソフトウェア比較と、TsaiらのGUIDE-seq検出済み部位。既知部位の回収率を調べる。元の比較には[UCSC hg19](https://hgdownload.soe.ucsc.edu/goldenPath/hg19/bigZips/)を使う。 |
| [Chaudhariらの比較研究・Supplementary File S3](https://doi.org/10.1089/crispr.2020.0053)・[NCBI BioProject PRJNA670368](https://www.ncbi.nlm.nih.gov/bioproject/PRJNA670368) | hg38で、追加のシーケンスにより編集あり・なしを判定した部位。両方の判定がある範囲で適合率を調べる場合に使う。 |

### 検索の回収率と、候補の適合率を分けて測る

1. **環境を用意する。** ツールと参照ゲノムの版を記録します。まず公開データから、編集が確認されたoff-target部位のあるガイドを1〜2本選びます。
2. **候補を照合するスクリプトを作る。** 同じガイド、参照ゲノム、PAM、ミスマッチ上限、bulge条件で検索します。ガイド、染色体、鎖、座標の定義をそろえ、意図した標的はoff-targetの集計から外します。ガイド別に候補総数と、共通の検索条件内にある既知陽性の回収率を求めます。回収率の分母は、比較前に決めた既知陽性の総数です。測定済みの陽性・陰性がそろう場合は、判定可能な候補に限った適合率と、全候補に占める未判定の割合も記録します。GUIDE-seqで未検出の候補は未判定として扱います。
3. **小さな入力でテストする。** 一致する部位と一致しない部位を1件ずつ用意し、照合結果と回収率の分母を手で確認します。異なる参照ゲノムの座標は、変換と配列の照合を済ませてから使います。
4. **ログを取りながら本解析を行う。** 比較表にツールの版、検索条件、候補数、回収率、判定可能な範囲を記録します。順位も比べる場合は、同じ候補集合をCFDや[MOFF](https://github.com/MDhewei/MOFF)で並べ、上位20件に入った既知陽性の数を別に集計します。
